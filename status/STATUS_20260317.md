## Key decisions made

### Architecture
- **Auth modal pattern (Option B):** `_layout.tsx` owns the auth modal via `AuthModalContext`. Any screen calls `openAuthModal()` — never renders `Auth` inline. See CLAUDE.md → "Auth Modal Pattern".
- **New `tasks` table:** The old `tasks` table (no `user_id`, RLS disabled) was deleted by the owner and replaced with a proper user-scoped one.
- **`captures` as central table:** Every capture (text or voice) writes to `captures` first, then optionally to `tasks` / `shopping_items` / `journal_entries` based on AI classification.

### Packages
- **`expo-audio` not `expo-av`:** `expo-av` is deprecated in SDK 54. All audio recording uses `expo-audio`. See CLAUDE.md → Stack section.
- **`expo-haptics`:** Already installed, used for light/medium/success haptic feedback on mic gestures.

### Edge Functions
- **ElevenLabs Scribe** chosen for STT (not Whisper, not Deepgram) — best multilingual accuracy, critical for Chinese + English users.
- **Gemini 2.0 Flash** for classification — temperature 0.1 (lower than note-style's 0.4) for consistent output.
- **Never crash rule:** Both edge functions fall back to `unclassified` on any error. A saved unclassified item is always better than a lost capture.

### Env / secrets
- `SUPABASE_URL` and `SUPABASE_ANON_KEY` are always read from `process.env.EXPO_PUBLIC_*` directly in each file — never imported from `lib/noteHelpers.ts`. See CLAUDE.md.
- `GEMINI_API_KEY` and `ELEVENLABS_API_KEY` live in Supabase Secrets only — never in `.env`.

## Issues found and solved

| # | Issue | Root cause | Fix |
|---|-------|-----------|-----|
| 1 | `CREATE POLICY IF NOT EXISTS` SQL error | Supabase Postgres < 16 doesn't support this syntax | Changed to `DROP POLICY IF EXISTS` + `CREATE POLICY` in all migrations |
| 2 | Old `tasks` table name conflict | Existing broken `tasks` table had no `user_id` | Owner deleted old table; new migration uses `tasks` correctly |
| 3 | `expo-av` deprecation warning (SDK 54) | `expo-av` removed in SDK 54 | Migrated all audio code to `expo-audio` API (`useAudioRecorder`, `requestRecordingPermissionsAsync`, etc.) |
| 4 | TextInput loses focus every ~60ms | `useAudioRecorderState(audioRecorder, 60)` polled via `setState` every 60ms, re-rendering the whole screen | Removed `useAudioRecorderState`; replaced with a manual `setInterval` on `audioRecorder.getStatus()` that only runs during active recording |
| 5 | MIC button press does nothing | `PanResponder` created once in `useRef` — callbacks (`startRecording`, `cancelRecording`, `stopAndSubmitRecording`) were stale closures from initial render | Added `startRecordingRef`, `cancelRecordingRef`, `stopAndSubmitRef` — reassigned on every render so PanResponder always calls latest version |
